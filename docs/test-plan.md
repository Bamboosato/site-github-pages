# 初期構築の検証設計

## 前提と観点

Node.js 24、lockfileによる依存関係、両言語のPublic repo14件と確認記録を前提とします。Buildとブラウザー操作は同一出力・同一ブラウザーに対して逐次実行します。静的生成なのでランタイムのDB・API競合は対象外ですが、Buildキャッシュ、環境変数、言語別データの取り違えを確認します。

| 分類 | 観点 | 意図 |
| --- | --- | --- |
| 機能 | 5種のページ、詳細生成、カテゴリ表示、日付順、言語切替 | 必要な紹介情報へ両言語で到達できる |
| 非機能 | 静的HTML、metadata、base、キーボード・focus、読みやすさ | 公開形式や操作環境に依存せず利用できる |
| データ | Public一覧との掲載集合一致、必須項目、日付、共通ID、翻訳ペア、更新参照、任意URL・画像 | 掲載漏れやPrivate混入、不完全なデータを公開前に検出する |
| UI | Mobile / Tablet / Desktop、日本語・英語、長文、画像なし | 狭い幅や英語文言でも情報と操作を維持する |

## ケースの区分

| 区分 | 対象と期待結果 |
| --- | --- |
| 正常 | 確認したPublic repoすべてが両言語の紹介と更新履歴に対応する。言語ごとのtitle・description・OG・canonical・hreflangを生成する |
| 異常 | 必須項目不足、翻訳欠落、ID／slug重複、共通項目不一致、存在しないアプリ参照、不正日付・URLを検出して検証を失敗させる |
| 境界値 | 空コレクション、タグ0件、公開URL・画像なし、うるう日、rootとproject base、320px幅を確認する |
| 状態遷移 | 詳細ページで日→英→日と切り替えて同じアプリを保持する。英語選択後の一覧・Updates・About遷移も英語を維持する。翻訳のみの修正はupdatedAtを進めない |

## 実行順序と範囲

1. `npm test`：純粋なデータ／URL処理の正常・異常・境界・遷移。
2. `npm run check`：型とAstroテンプレート。
3. `npm run build`：Build前の実コンテンツ検証と全静的ページ生成。
4. `npm run validate:links`：生成HTMLの内部リンク、画像、fragment、metadata、言語維持、見出し階層。
5. `npm run verify:bases`：rootとproject baseで順番にBuild・リンク検証。
6. `npm run verify:markdown`：一時的な翻訳ペアと画像を追加してBuildし、本文・metadataの変更反映を確認する。終了時にテストデータを除去し、元のサイトを再Buildする。
7. 実ブラウザー：Home／一覧／詳細／Updates／Aboutの代表操作、日英切替、複数画面幅、キーボード。

E2Eは初期実装の共有部品と主要遷移を対象にする。全ルートのリンクとmetadataは生成HTML検証で網羅し、実ブラウザーでは代表ページを選ぶ。クロスブラウザー・別OS・実スマートフォン・公開サイトは未実施の場合に明記する。

## 証跡と切り分け

実行コマンド、失敗ファイルと項目、画面幅、URL、ブラウザー操作、スクリーンショットを記録する。結果は `docs/verification-results.md`、画像はローカルの `artifacts/` に保存する。再現しない問題は結論を急がず、フォント・キャッシュ・Build切替タイミング等の仮説を整理する。
